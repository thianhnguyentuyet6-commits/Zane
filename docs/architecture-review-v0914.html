Deepening opportunities: turn shallow modules into deep ones, improve testability and AI-navigability

1. Tools Module - 单文件26工具过重

Files: backend/tools_impl.py (933行, 48KB) + backend/tool_registry.py + backend/policy/undo_stack.py

Strong

Problem - Shallow Module

tools_impl.py 包含26工具，接口复杂度≈实现复杂度，933行单文件难以维护。理解一个工具需阅读整个文件，测试需mock整个ToolExecutor。删除测试：删除会分散复杂度，但当前集中也造成大文件。违反locality - pure functions extracted for testability but bugs hide in how they're called.

Before: 单文件26工具

Solution - Deepen Module

按Windows功能分层：FileTools, ProcessTools, WindowTools, VisionTools, SystemTools，每个深模块有清晰接口。ToolExecutor作为facade，内部委托。每个子模块可独立测试，接口是test surface。Leverage: 一次修改文件工具只需改FileTools，不触及其他。Locality: 工具逻辑+测试+安全检查在同一模块。

After: 分层深模块

2. Frontend 单文件78KB过重

Files: frontend/index.html (1383行, 78KB) + frontend/js/*.js 14文件冲突

Strong

Problem - Shallow + Duplicated

index.html单文件包含所有视图逻辑+CSS+JS，78KB，难以测试。旧版有app.js+app_windows.js同定义window.loadSystem冲突，事件覆盖导致点击无反应。理解一个视图需阅读整个文件。Deletion test: 删除会分散到多文件，但当前单文件也难以维护。No locality - UI逻辑+API调用+渲染混一起。

3. Memory 概念分散6文件

Files: backend/memory/memory.py + simple_mem.py + forgetting.py + vector_memory.py + data_flywheel.py

Worth exploring

Problem - Bouncing Between Modules

理解记忆需bounce between 6文件：memory.py 4层统一, simple_mem.py压缩, forgetting.py遗忘曲线, vector_memory.py向量, data_flywheel.py数据飞轮。概念分散，接口浅，每个文件小但关联紧密。Tests need to mock multiple modules. Leaks across seams - forgetting logic leaks into memory.py.

Solution - Deep Memory Module

统一为Memory深模块，内部包含layers, compression, forgetting, vector, flywheel作为私有实现，外部接口add_memory(), search(), forget_low_value(), get_stats()。CONTEXT.md中定义"Memory"概念，深模块名匹配。Interface is test surface - 测试只需调接口，不需知内部。Locality: 记忆相关逻辑+测试在同一模块。

4. Routers 18文件API分散

Files: backend/routers/*.py 18文件 110API

Speculative

Problem - Interface Dispersion

18路由文件，每个小，API分散110API。理解系统状态需查system_router.py, windows.py, platform等多个路由。Shotgun surgery - 添加一个Windows功能需改多个路由文件。Interface nearly as complex as implementation - 每个路由文件只是薄包装。

Solution - Domain Routers

按领域合并：system.py (system+windows+platform), memory.py (memory+vector), evolution.py等，深模块每个领域。每个领域路由有统一前缀和清晰接口。Two adapters = real seam - 当有Windows和Linux两种实现时，seam才真实。当前可先按领域合并，减少文件数，提高locality。

🏆 Top Recommendation: Tools Module Deepening

Why first: Hot spot - 最近39次提交中17次改frontend/index.html, 6次改tools_impl.py，是最频繁变更区域。Shallow module造成最大friction - 每次加工具都要改933行文件，测试困难，AI难以导航。Deepening后leverage最高 - 文件工具修改不影响进程工具，Windows真实测试可按模块进行。符合YAGNI - 未来还会频繁加Windows工具。
